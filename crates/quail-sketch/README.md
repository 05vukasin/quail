# quail-sketch

Per-file similarity sketches. Namespace `sketch.*`. A later service indexes them to find
near-duplicates, versions and documents cut from one template across millions of files; this
crate only **emits** compact, stable sketches and LSH keys, one file at a time. Built on
`quail-text` (normalization, tokens, folding, pinned XXH3 hashes); nothing is re-tokenized or
re-hashed here.

## Analyzers and keys

All require the `document` artifact.

| analyzer | profile | keys | value | compare | bar |
|---|---|---|---|---|---|
| `sketch.minhash@1` | Fast | `sketch.minhash` | Bytes, 128 rows × u32 LE | `jaccard_estimate` (share of equal rows) | near-dup J ≥ 0.60, version J ≥ 0.90 |
| | | `sketch.minhash_bands` | List of 32 U64 (band index mixed in) | any shared key = candidate | P(hit) = 1 − (1 − J⁴)³² |
| | | `sketch.minhash_shingles` | Int | gate | ≥ 40 or nothing is emitted |
| `sketch.simhash_text@1` | Fast | `sketch.simhash_text` | U64 | `hamming` | ≤ 6 ≈ J ≥ 0.9 |
| `sketch.simhash_template@1` | Fast | `sketch.simhash_template` | U64 | `hamming` | ≤ 8 same template |
| `sketch.layout@1` | Fast | `sketch.layout`, `sketch.layout_blocks` | U64, Int | `hamming` | ≤ 6 same layout (PDF geometry) |
| | | `sketch.structure` | U64 | `hamming` | ≤ 8 same structure (headings, lists, tables) |
| | | `sketch.headings` | U64 | equality | same heading skeleton |
| `sketch.invoice_layout@1` | Fast | `sketch.invoice_layout`, `sketch.invoice_labels`, `sketch.invoice_number_patterns` | U64, Int, Int | equality (and labels ≥ 3 to call it an invoice) | |
| `sketch.text_key@1` | Fast | `sketch.text_key` | Bytes, 16 (XXH3-128) | equality | same words (≥ 400 chars) |
| `sketch.minhash_sada@1` | Standard | `sketch.sada_minhash`, `sketch.sada_minhash_bands`, `sketch.sada_shingles`, `sketch.sada_template` | Bytes 128 × u64 LE, List of Text, Int, U64 | as the Python service | see below |
| `sketch.page_phash@1` | Standard (needs `raster`) | `sketch.page_phash`, `sketch.page_phash_pages` | List of U64, List of Int | `hamming` per page | ≤ 8 per page, all pages, equal counts |

Pure helpers: `hamming(a, b)`, `jaccard_estimate(sig_a, sig_b)` (works on both signature
layouts), `minhash::band_collision_probability(j)`, and every sketch as a function
(`minhash::text_minhash`, `simhash::text_simhash`, `template::template_simhash`,
`layout::{geometry_sketch, structure_sketch}`, `invoice::features`, `phash::phash`,
`text_key`, `sada::*`).

### How the service should use them

1. **Exact**: `sketch.text_key` equal → same words (another rendering, re-save, case or script
   change). `hash.blake3` equal → same bytes.
2. **Candidates**: index `sketch.minhash_bands` (32 keys per file, one table); a shared key
   makes a candidate pair. Rank candidates by shared keys, cap them.
3. **Confirm**: `jaccard_estimate` ≥ 0.90 → version/copy on the text alone; 0.75–0.90 only
   with an identity tie (same invoice or agreement number, same title); ≥ 0.60 near-duplicate.
   Next month's invoice from one template typically scores 0.6–0.9 on short bodies: identity
   guards (different invoice numbers → never versions) belong to the service.
4. **Template**: `sketch.simhash_template` within 8 bits → same template (index by 4 × 16-bit
   blocks for ≤ 3 bits exact, or multi-probe for 8). Combine with an issuer key when known.
5. **Layout**: `sketch.layout` within 6 bits → same form/layout; `sketch.structure` within 8
   for DOCX; `sketch.headings` equal → same outline.
6. **Scans**: compare `sketch.page_phash` page by page only when page counts agree; every
   page ≤ 8 bits → same pages (then a lower text bar, e.g. 0.75, is fair to OCR drift).

## Definitions (stable)

- **Text** = page texts (pages needing OCR skipped) joined by `\n`, normalized with the
  `quail-text` defaults; at most `Limits::max_text_bytes` (problem recorded when cut).
- **Shingles** = `quail_text::shingle::text_shingles(text, 3, &FoldOptions::KEY)` (folded
  word 3-shingles; Latin and Cyrillic spellings agree).
- **MinHash** = 128 permutations `(a·x + b) mod (2^61 − 1)` over the 64-bit shingle hashes
  (coefficients: `src/coeffs.rs`, generated by `tools/quail-sketch/gen_minhash_coeffs.py`,
  identical to CPython's `random.Random(0x5ADAF19315)`); a row stores the low 32 bits of its
  minimum. Bands: 32 × 4 rows, key = XXH3-64(`[band] ‖ 16 row bytes`).
- **SimHash text** = SimHash-64 of the shingles weighted `1 + floor(log2(count))`.
- **Template** = SimHash-64 of the *set* of masked words: URLs, e-mails, dates, amounts,
  other numbers, letter-digit codes, month names and capitalized words that do not start a
  line or sentence become `<url> <email> <date> <amount> <num> <code> <month> <name>`.
- **Layout** = SimHash-64 of quantized block boxes (x in eighths, y in twelfths, height class),
  kinds, zones, images and page size of the first 8 pages (page classes first / second /
  rest). **Structure** = SimHash-64 of block-kind symbols (heading levels, list, table shape,
  paragraph runs) and their 3-grams; needs two block kinds, so all-paragraph PDFs get none.
- **pHash** = 32 × 32 box-filtered gray, DCT-II, top-left 8 × 8 > median; embedded scan when
  the page is one image, else rendered at 36 dpi; at most 16 pages.

The module docs carry the full definitions. `tests/golden.rs` pins every sketch of a generated
sample. **A golden diff means stored sketches change: bump that analyzer's version**
(`sketch.<name>@N+1`). The crates that decide the values are pinned with `=` versions
(`xxhash-rust`, `blake2b_simd`, `regex`, `fancy-regex`, plus `quail-text`'s own pins).

## Python compatibility (`sketch.minhash_sada@1`, `sketch.invoice_layout@1`, `sketch.headings`)

A port of the fingerprints an existing Python service stores (tokens `<\w+>|\w+` over
`lower()`, BLAKE2b-64 personalized `sada-fp-v1`, the same 128 permutations and 32 × 4 bands,
bucket strings `"band:hex"`, template SimHash over entity-masked unigrams, invoice labels +
number shapes, heading skeleton). Python's `\w`, `\s`, `\b` and case-insensitive `i` are
emulated exactly. Given the same text the values are identical: checked on the text of 380
private PDF/DOCX files (352 version signatures, 352 bucket lists, 352 template
fingerprints, 276 invoice fingerprints: 100 % equal) and on 90 000 random strings over a
pool of tricky Unicode (marks, superscripts, `İ ı ſ K`, U+001C–U+001F, NBSP, U+2028, …).
The Python service's thresholds: version ≥ 0.90, ≥ 0.75 with an identity tie, near-dup
≥ 0.60, another rendering of one invoice < 0.40, template within 8 bits, scanned page within
8 bits. It masks caller-supplied entity names too; this port is called without them.

380 files (369 PDF via `quail-pdf` PR #7, 11 DOCX), 352 with enough text for a signature,
61 776 pairs. Supplier folder used as a rough label (base rate 23 % of pairs).

|---|---|---|
| MinHash J ≥ 0.6 / ≥ 0.75 / ≥ 0.9 | 580 / 135 / 36 | 98 % / 90 % / 72 %¹ |
| LSH bands: candidate pairs | 3 915 (6 % of pairs), recall of J ≥ 0.6 pairs 580/580 | |
| SimHash text ≤ 6 | see `simhash` docs: all 36 J ≥ 0.9 pairs within 5 bits | |
| Template ≤ 8 | 3 429 | 100 % |
| Layout ≤ 6 | 3 434 | 98 % (99 % same document kind) |

¹ exact copies filed under several folders. Spot checks (looked at by hand): of the 36 pairs
with J ≥ 0.9, 34 are copies, re-uploads, renderings or versions of one document and 2 are
consecutive short invoices from one template (the identity guard's job). Template collisions
with J < 0.3 (52 pairs) are, in a 20-pair sample, all invoices of one supplier from one billing
template (one pair across two suppliers using the same AP-portal form). Layout collisions with
J < 0.1 (67 pairs, 25 sampled) are AP-portal invoice forms and schedules of one MSA family; one

## Limits and robustness

- Text: `Limits::max_text_bytes` (problem when cut); deadline checked per page and after
  shingling. Pages needing OCR are skipped by the text sketches.
- Structure: at most 20 000 blocks; layout: first 8 pages; pHash: 16 pages (warning beyond),
  render refused by the raster over `max_render_pixels`, failures per page are warnings.
- The `sada` port's regexes run on `fancy-regex` with its backtracking limit: hitting it is a
  problem on the record (sketch skipped), never a panic.
- No `unsafe`, no panics on content (tests feed control characters, combining marks, 1 MB
  words, long `1,1,1,…` and `A A A … Ltd` runs).
